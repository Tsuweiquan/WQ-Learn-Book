1. Learning method

Every topic is studied at three altitudes, always in this order. Start wide to see the shape, drop into the reasoning, then land on working code.

L1High

High-level architecture

Several reference architectures for the topic, side by side.

  • Diagram of each architecture with its main components and data flow
  • When each one fits: scale, team size, cost, cloud (AWS / GCP) mapping
  • What changes between them and why
L2Mid

Theory

What the topic is, in depth, and why the industry does it this way.

  • Core concepts and vocabulary
  • The problems it solves, and what came before it
  • Common pros and cons, with trade-offs stated plainly
L3Ground

Implementation

Concrete examples you can run, plus a way to verify them locally.

  • Code and config examples (Terraform, YAML, scripts as relevant)
  • A local test method, e.g. kind, docker compose, emulators
  • What "working" looks like: expected output and checks

3. Page template

Every topic page follows this exact outline, so any page can be skimmed the same way.

Header
Topic name, one-line summary, date added, area tag.
Table of contents
Always at the top, linking to every section below.
§1 Architecture
Multiple architecture examples:
  1. Architecture A: diagram, components, flow
  2. Architecture B: diagram, components, flow
  3. Comparison: when to choose which
§2 Theory
  • What it is
  • Why the industry does it this way
  • Problems it solves
  • Pros and cons
§3 Implementation
  • Step-by-step example with code
  • How to test it locally
  • Expected results and cleanup
References
Links to official docs and sources used for the page.

4. House rules

Sourced, not guessed

Content comes from documented, established practice. Anything uncertain is marked as uncertain.

Technical first

Written for an engineer: precise terms, real config, no filler.

Runnable locally

Every implementation section ends with a way to test it on a laptop.

Corrections welcome

Wrong assumptions get called out and fixed, on the page and in the conversation.
